## 7. 主要质量短板

1. **动画表现力不均衡**：数学/物理的"过程类"镜头（曲线生长、光路、电流、原子重排）表现较好；概念课（一次函数、细胞结构）仍有较多"文字逐行出现"，接近动态 PPT。这是当前最大短板。
2. **示意图精细度**：人物、实验装置为简笔示意；虽然知识正确，但真实感不足。
3. **人工评审独立性不足**：评分为开发 Agent 自评，存在确认偏差；关键知识未做第三方复核。
4. **自动检查的边界**：只检测文字相关布局与像素稳定性，无法判断"两个图形错误重叠""箭头指向错误"。
5. **节奏**：个别镜头信息密度偏高（如全等的判定对照表），字幕停留时间紧。

## 8. 已知限制

- 采样离散：0.2s 内的瞬时错误可能漏检。
- 字体依赖系统："Microsoft YaHei" 缺失时字幕换行会变，需重跑。
- 无音频：默认无配音，靠字幕；对低龄学生的吸引力有限。
- 未做移动端适配（16:9 等比缩放，竖屏会留黑边）。
- 未实现视频导出；如需 MP4，需要额外的逐帧录制与编码步骤。

---

## 9. 后续优化建议

1. **补一类"过程动画"配方**：为"参数变化""状态转移""因果链"提供可复用的镜头组件，减少文字揭示。
2. **图形级布局检查**：检测箭头端点是否落在目标图形边界、两个填充图形是否异常重叠。
3. **引入独立评审**：用另一个模型只看 `lesson.html` 与评分表打分，比较与自评的差异。
4. **真实课堂试用**：至少 3 个知识点做 5 名学生的前后测，验证"看懂"而非"好看"。
5. **视频导出**：用确定性 seek + 逐帧截图 + ffmpeg 合成，保证与 HTML 完全一致。
6. **建立新保留集**：v1.2 之后新增 4 个未参与开发的知识点，恢复无偏评估。

## 附：v1.3 现场验证（《孟德尔第一定律》）

**用途**：不是补充凑数，而是验证"给一个新知识点，按 Skill 流程能否一次做出来"。

| 项 | 结果 |
|---|---|
| 学科 / 学段 | 生物 · 八年级下 |
| 时长 | 194s / 9 镜（按 5 个核心点 + 实验对照 + 抽象过程估算） |
| 自动检查 | 19/19 通过（含 11 个 probe） |
| 人工评分 | 91（知识 24 / 逻辑 18 / 动画 17 / 视觉 13 / 时间轴 9 / 工程 10） |
| 综合分 | **94.6** |
| 首次构建到通过 | 2 轮：自动检查发现柱状图标注重叠；人工复核发现棋盘格出现 `dD` |

**过程中发现的两个问题**

1. **技能发现失败**：本会话内按名称调用 Skill 返回 not found。原因是技能清单在会话启动时加载，新放入 `.workbuddy/skills/` 的包要等下一次会话。包本身结构、frontmatter、路径均正确。这是交付物最实际的可用性缺陷。
2. **知识性错误被人工抓住**：Punnett 格的 `dD` 写法。自动检查只验证数值（3 高 1 矮），不验证记法规范；说明"基因型显性在前"这类约定必须写进学科规则，而不能指望 probe。已在 `references/subject-guidelines.md` 的生物部分补充。

**累计（13 例）**：自动 13/13，平均 100；人工 85.2；综合 91.1，最低 87.4。
